# 旧 React 游戏接口与流水线

新参考质感优先使用 cinematic-profile.md；母提示词 v1.0 仅作旧接口背景，视觉规范与是否确认以当前 SKILL.md 为准。

> 引擎与母提示词都在 `~/Desktop/zcode/ai-explain-game/`；本文件是"怎么从一段口播文案走到一条 MP4"的施工细节。
> 视觉规格见 [style-dna.md](style-dna.md)。已跑通的实例：**第 3 期 15 秒样片**（3 场 / 15.0s / 1080p30，主角＝新设计的"夜班档案员"）。

## 0. 一句话总览

**口播文案 → 事实核查 → 分镜（按语义拍设计动作）→ 场景代码 → 逐句配音定时间轴 → 逐帧导出 → 成片 + 静帧给他审**

| 步 | 做什么 | 命令 / 文件 |
|---|---|---|
| 1 | 文案：一句一行，字幕＝口播，每句 ≤22 汉字、`[[关键词]]` 只 1 个 | 新期内容文件 `src/content/episode-<slug>.ts` |
| 2 | 事实核查：数字/术语/年份/人名逐个找出处；核不到就删或标"示意" | 记进交付说明 |
| 3 | 分镜：按语义拍设计动作，填场景表（背景/主角/元素/字幕/动效/光源） | 表在 §2 |
| 4 | 场景代码：`src/scenes/<slug>0.tsx` 写 `SceneDef`；`src/scenes/index.ts` 注册一期 | §3 + §4 |
| 5 | 配音 + 时间轴：先 TTS 量真实时长，再回填 `at` 与场景时长，最后拼轨 | `scripts/voice_track.py` |
| 6 | 出片 + 质检：静帧预检 → 整片导出 → 抽帧自检 → **渲完直接进对话框给他审** | `scripts/stills.mjs` · `scripts/render_episode.mjs` |

启动：`cd ~/Desktop/zcode/ai-explain-game/game && npm run dev`
（⚠️ 端口被占时 Vite 会自动换到 5274 —— **以终端打印的地址为准**，脚本的 `--url` 要对上）

## 1. 输入：文案的形态

- 一句一行；**字幕全文＝口播全文**，不要另写一套。
- 单行 ≤22 个汉字，超长就拆成两句（同一场景内推进），**永不折行**。
- 每句只标 1 个 `[[关键词]]` —— 字幕会把它染成橙色。
- 短钩子优先：一个让人停住的反差（数字/事实/说法），但数字必须可查。
- 禁用：过渡话（"接下来我们讲…"）、负向钩子（"不知道就完了"）、空话（"非常非常重要"）。

## 2. 分镜表（每场景一行，有实质歧义才澄清，已授权样片直接执行）

| 字段 | 填写要求 | 例 |
|---|---|---|
| 时间 | `mm:ss–mm:ss`（**先按 4.5 字/秒估**，第 5 步再用真实配音时长校正） | `00:00–00:05.2` |
| 章节 | 第几章 / 章名（顶部章节轨一格） | `答得太顺` |
| 背景 | 8 个成品背景选一（`city` `worldmap` `library` `terminal` `starfield` `warning` `lab` `workshop`） | `terminal 书桌终端房` |
| 主角 | 站位 / 姿势（`idle` `talk` `point` `walk`）+ 皮肤 + 配饰 | `夜班档案员 · 站灯下 · glide` |
| 主元素 | 从元素库挑 1 个 + 出场时机（**锚定哪个口播词**） | `B12 聊天气泡：说到"越顺"时弹出` |
| 辅助元素 | ≤2 个 | `B13 警示面板：说到"对"时压上来` |
| 字幕 | 全文（含 `[[关键词]]`） | `它答得越顺，你越容易[[当真]]。` |
| 动效 | 运镜（1.2–2.5s 推到位的写法）+ 元素动效 + 结束方式 | `z 1.02→1.24 推近 3.6s 停稳；高亮框画完定格` |
| 光源 | 主光源在哪 | `桌灯暖光；屏幕荧光补面光` |

**节拍**：一个 5 秒场景 ≈ 3 拍 —— 就位+首句浮现 / 主元素按口播词启动 / 收束定格。
每个语义拍安排有意义的动作；允许讲述、停稳与留白，不用装饰动画强行填满。

## 3. 写场景代码：SceneDef

```ts
export const m01: SceneDef = {
  id: 'm01', dur: 5200,                     // 毫秒，第 5 步按真实配音校正
  bg: 'terminal',                           // 背景
  script: SCRIPT.m01,                       // 章节 + 地点卡 + 字幕（来自 content 文件）
  cam: push(166, 96, 1.02, 1.24, 3600),     // 机位：1.2~2.5s 推到位后停稳
  hero: (t) => ({ x: 44, y: 100, pose: t > 600 ? 'talk' : 'idle', skin: SKINS.archivist, acc: 'glasses' }),
  build: (t) => (<> …元素层… </>),          // 元素出场时机都写在这里（t 是场景内毫秒）
};
```

- **机位**（`scenes/kit.ts`）：`push(x, y, z0, z1, ms)` 推近、`hold(x,y,z)` 定住、需要多段用 `camAt(t, [{at, x, y, z}, …])`。坐标是 **320×180 艺术坐标**（x∈0–320，y∈0–180）。**动完必须停稳**。
- **主角**：`pixel/character.ts` 的 `SKINS` 三套皮（`classic` / `archivist` 夜班档案员 / `host` 深夜电台）＋ 配饰 `acc: 'glasses' | 'headset' | 'cap'`。要新角色就加一套皮（12 个色键）+ 挑一个配饰，只适合简便换皮；用户要新人物时还需改变轮廓或特征结构。
- **元素层**：`ui/elements.tsx` 里 B1–B21（打字机 / 大数字 / 算式黑板 / 金边面板 / 填空 / 选项 / 星级 / A-B 双卡 / 道具卡 / 节点图 / 聊天气泡 / 警示面板 / 进度条 / 折线图 / 清单 / 徽章 / 节点牌 / 参数旋钮 / 工具调用 / 关卡牌）。
  坐标是**屏幕像素**（1280×720 设计稿），DOM 顺序＝叠放顺序（要底衬就先写底衬）。
  出场进度一律用 `p(t, 起, 时长)`，别自己算缓动。
- **一场景只讲一件事**：主元素 1 个 + 辅助 ≤2 个。元素不许压字幕带（屏幕下方 ≈ y 600 以下），不许压主角脸。
- **交互点**（可选）：`Gate`。纯观看时静置 3 秒自动选默认项；出片走录制模式时直接取第 0 项。

## 4. 注册这一期

`src/scenes/index.ts` 的 `EPISODES` 里加一个 `pack(...)`（id / tab / 标题 / 副标题 / 署名 / 三件事 / 章节 / 场景数组）。
时间轴（offsets/total）由各场景 `dur` 自动累加 —— **所以 `dur` 错了，字幕和配音就全错位**。

## 5. 配音与时间轴（后端自带，先量后填）

**本技能不带任何内置音色。** 配音后端由使用者自己提供 —— 一个"给文本、还音频"的 HTTP 接口，或一条本地 TTS 命令；脚本只做三件事：逐句调用你的后端 → 量出真实时长 → 按时间码拼轨。

先跑一次 `--check` 合成一句试听，确认接好了再开始逐句：

```bash
python3 scripts/voice_track.py --check
```

### 5.1 接法 A：HTTP API

脚本对接口的约定（请求）：

```
POST <你的 URL>
Authorization: Bearer <key>          # 给了 key 才带
Content-Type: application/json
{"text": "要合成的一句", "voice": "音色标识（没配就不带）"}
```

返回以下任一种都认（字段名不按默认给，就用配置的 `audio_field` 指定）：

| 返回形态 | 例子 |
|---|---|
| 音频字节 | `Content-Type: audio/mpeg`，body 即 mp3/wav 字节 |
| JSON + 直链 | `{"audio_url": "https://…/a.mp3"}`（也认 `url` / `audio` 给直链） |
| JSON + base64 | `{"audio_base64": "…"}`；往一层里找也认（`{"data": {"audio": "…"}}`） |

```bash
python3 scripts/voice_track.py --tts-api https://your-tts/api --tts-api-key sk-… --check
```

（HTTP 走系统自带的 `curl` 发请求，不走 Python 的证书链，少踩 SSL/代理的坑。）

请求体字段名不一样（比如要叫 `speaker` / `input`）就在配置里改 `body` 模板，`{text}` `{voice}` 会被替换：

```json
{"type": "http", "url": "https://your-tts/api", "key": "sk-…", "voice": "你的音色",
 "body": {"text": "{text}", "speaker": "{voice}"}, "audio_field": "audio",
 "headers": {"X-Client": "pixel-explainer"}, "timeout": 120}
```

（要挂代理加 `"proxy": "http://127.0.0.1:7890"`；接口用自签证书加 `"insecure": true`。）

### 5.2 接法 B：本地 TTS 命令

```bash
python3 scripts/voice_track.py --tts-cmd "your-tts --out {out} --text {text} --voice {voice}" --check
```

- 模板含 `{text}` / `{out}` / `{voice}` 占位符就按模板原样执行（参数名随你的 CLI）；**`{out}` 必须有**。
- 没有占位符时按约定追加：`<cmd> <文本> --out <文件>`，音色非空再加 `--voice <音色>`。
- 只给一个 `.py` 路径也行（自动用 `python3` 跑）。

### 5.3 配置从哪来（优先级：命令行 > 环境变量 > 配置文件）

| 位置 | 写法 |
|---|---|
| 命令行 | `--tts-api` / `--tts-cmd` / `--tts-api-key` / `--voice`（`--speaker` 同义） |
| 环境变量 | `TTS_API_URL` / `TTS_CMD` / `TTS_API_KEY` / `TTS_VOICE` / `TTS_CONFIG` |
| 配置文件 | `tts.config.json`：`--tts-config` 指定 → `$TTS_CONFIG` → `<work>/` → 当前目录 → `~/.config/ruic-pixel-explainer/tts.json` |

key 放配置文件或环境变量，别写进要提交的工程里。

**已经有成品音轨**（真人录音、别的工具合成）就跳过合成，直接进第 6 步把 `--audio` 指过去；但字幕与动作仍要按它的真实时长排，用 `ffprobe` 量。

### 5.4 步骤

```bash
# ① 逐句 TTS + 报真实时长（定时间轴用）
python3 scripts/voice_track.py --lines lines.json --work <工作目录> --tts-only
#    输出每句真实时长 → 按它排：句子间隔 250~400ms，尾句后留 600~900ms
# ② 定好时间码后拼一条整轨（at = 整片时间轴上的绝对毫秒）
python3 scripts/voice_track.py --lines lines-abs.json --work <工作目录> --out voice.wav
```

- `lines.json`：`[{"at": 450, "text": "它答得越顺，你越当真。"}, …]`
- **时间轴必须由真实语速决定**：中文口播约 4.5 字/秒，但句读、数字、英文会把节奏拉长 —— 实测 6 句短片比"字数估算"多出约 0.8 秒。
- 逐句音频按「文本 + 后端」缓存（`line-XX.<ext>.cache.json`）：同批重跑不重复调用；改字或换后端自动重合成。
- 拼轨会**先把每句摆到它的 `at`**（前面补静音），所以画面时间轴和配音天然对齐；段落重叠默认拒绝（明确要叠声才传 `--allow-overlap`），不裁句尾凑预算。

## 6. 出片

```bash
# 静帧预检（先看版式，别直接渲染）
node scripts/stills.mjs --url http://127.0.0.1:5274/ --ep <slug> --out stills --times 1.2,3.9,7.6,11.2,14
# 整片导出（30fps 定帧；有配音就一起混）
node scripts/render_episode.mjs --url http://127.0.0.1:5274/ --ep <slug> \
  --out <片名>-像素重建.mp4 --audio voice.wav --fps 30 --dsf 1.5 --size 1920x1080
```

- 原理：画面是**时间 t 的纯函数**，脚本把 t 定到每帧、截 `.frame`、按序喂 ffmpeg —— 与实时录屏无关，逐帧确定（脚本默认抽 5 帧各截两次自检，字节应一致）。
- 分辨率口径：`--dsf 1.5` 让 1280×720 视口截图直接落在 1920×1080（艺术格 ×6），不用再次下采样—— **整数倍**，像素块不变形；要 720p 原样就 `--dsf 1 --size 1280x720`。
- 耗时量级（M 系列 Mac）：约 **0.22 秒/帧** → 15 秒片 ≈ 1.6 分钟；3 分钟片 ≈ 20 分钟。
- 有音轨时按画面长度补齐静音（不用 `-shortest`），片子不会被音频截短。
- `?rec=1` 是录制模式：控制条不出画，交互点直接取第 0 项；章节轨/署名/地点卡/字幕照常。

## 7. 质检与交付

| 检查 | 做法 | 判据 |
|---|---|---|
| 类型 | `npx tsc --noEmit` | 通过 |
| 画面 | 静帧逐场看（`stills.mjs`）+ 成片抽帧 | 无空场、没压字幕、元素锚定口播词、字号够大 |
| 音频 | 听整条音轨（先发他听） | 不压句、不错字 |
| 成片 | `ffprobe` | 1920×1080 / 30fps / 时长对得上 / 有 AAC 音轨 |
| 交互（有交互点才做） | 点一遍 + 静置 3 秒自动继续 | 纯观看不卡住 |

**交付**：成片 MP4 给绝对路径（默认落 `~/Desktop/zcode/`，只有他明说才放桌面）+ 每场景静帧 + 口播稿 + 一句话规格。
**渲完直接进对话框由他审**，不要先自审。

## 8. 坑（真踩过的）

1. **`dur` 是唯一时间源**：场景 `dur` 累加成整片时间轴；改文案不改 `dur`，字幕和配音就错位。
2. **先量后填**：TTS 真实时长与"4.5 字/秒估算"能差 10%；先跑 `--tts-only` 再定 `at`。
3. **音轨别用 `-shortest` 收尾**：音频短一点就会把画面尾巴吃掉（缺失 0.13 秒）；脚本已改成补静音到画面长度。
4. **dev server 端口**：5273 被占时 Vite 换 5274 —— 脚本 `--url` 必须跟着改，否则渲的是旧服务上的旧代码。
5. **`FillBlank` 这类元素自带绝对定位**：要底衬就**先写 PanelBox 再写它**（DOM 顺序＝叠放顺序），否则字直接压在书架上。
6. **对比卡 `min-height:190px`**：文案只有一行时卡片空一半 —— 补成两句（或换更短的卡型）。
7. **CSS 墙钟动画不可复现**：打字机光标 `.cursor` 的 blink 是 CSS 动画，逐帧导出时相位随机（只有光标也必须吃场景时间，修正前不能通过确定性检查）；别的动画都吃 `t`。
8. **字体没加载完就开画**：等 `document.fonts.load` 完成（工程已内置等待，出现在路由/等待逻辑里别删）。
9. **交互点在成片里不许弹**：录制模式会自动取第 0 项；出片前用 `?rec=1` 跑静帧确认控制条没入画。
10. **系列换款**：仅在用户要求多账号或系列区分时改变包装。要求参考片感觉的任务先稳定角色、场景与像素规范。
